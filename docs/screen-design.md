# CorvusTrack 画面設計案

更新日: 2026-09-13
状態: 第4案・レビュー中。横・Foldの左側ナビゲーションレールと、高さを抑えたカードを反映。具体的な寸法は提案段階。
参照: [基本設計](basic-design.md)

## 1. 全体構成

デザインシステムはMaterial 3 Expressive（M3E）に従う。Android実装では公式コンポーネント・テーマの色、形状、タイポグラフィ、状態表現、動きを基準にする。
会話内の画面案は配置検討用であり、M3Eの正式なコンポーネントやモーションを再現した実装ではない。
参照: [Material Design公式](https://m3.material.io/)、[公式Android Expressive FAB実装資料](https://github.com/material-components/material-components-android/blob/master/docs/components/ExtendedFloatingActionButton.md)。

メインから履歴一覧・設定へ移動し、履歴一覧から履歴詳細を開く。
メインのアプリ名タイトルバーをなくし、ナビゲーションの「地図・履歴・設定」で移動する。縦・狭幅は下部バー、横・Foldなど十分な幅がある場合は左側レールとする。アイコンとラベルを併記し、現在の画面を選択表示する。
履歴詳細は履歴配下とし、ナビゲーションの項目は増やさない。履歴・設定では内容の見出しを表示できるが、画面遷移のためのタイトルバーは置かない。
切り替えは端末名ではなく利用可能な画面領域で判断し、狭い分割画面などでは下部バーへ戻す。横向きならSDKが必ずレールを選ぶとは限らないため、幅・高さ・姿勢を踏まえて本アプリの切り替え条件を実装時に設定する。画面案の520pxは比較用であり、Androidのdp閾値としては確定しない。
参照: [Android公式のAdaptive navigation](https://developer.android.com/develop/adaptive-apps/guides/build-adaptive-navigation)。
記録の開始・停止はメインで行う。別画面では記録中の表示をタップするとメインへ戻れる。
Androidの戻る操作でも前画面へ戻る。画面遷移は記録を停止させない。

## 2. メイン

### 共通領域

- 上部タイトルバーは置かない。地図上の操作はOSのステータスバー・カットアウト領域を避ける。下部バー・左側レールはOSのジェスチャー領域と区別する。
- 地図: 最大限の領域を確保。地図の向きと現在地追従のボタンを地図上に置く。
- 記録状態: 待機中／記録中／測位待ち／位置情報を取得できませんを文字で示す。色だけに依存しない。
- 情報パネル: 速度、距離、経過時間、開始／停止操作。
- 現在地追従・地図の向きはアイコンボタンを基本とする。読み上げ名と長押しの説明を用意する。履歴・設定はナビゲーションの項目とする。Android実装時のアイコンはMaterial Symbols等で統一する。
- 開始／停止はアイコンと文字を併記する案とし、状態が変わってもボタンの外形と位置を維持する。
- 停止後に情報パネルへボタンや行を追加しない。「記録を保存しました」と「見る」アクションをスナックバーで表示し、地図やカードを押し縮めない。消えた後もナビゲーションの履歴から参照できる。
- Mapboxのロゴ・帰属表示に必要な領域を確保し、操作ボタンや情報パネルを重ねない。

### 配置案

| 画面領域 | 配置 |
|---|---|
| 縦・狭幅 | 地図上の下部に左右の余白を持つフローティングカード。速度を大きくし、距離・時間を下に並べる |
| 横・十分な幅 | 左にナビゲーションレール、地図上の右側に低めのフローティングカード。速度を1行、その下に距離・時間を横並びにし、開始／停止を下段に置く |
| Foldなど幅・高さともに余裕あり | 左にナビゲーションレール、残りの地図領域の左下に幅約半分の不透明なフローティングカード。速度を1行、距離・時間を横並びにし、開始／停止もカード内に置く |

レイアウトは機種名で分岐しない。実装時にウィンドウ領域、文字サイズ、システムバー、折り目・遮蔽領域を考慮して切り替え条件を決める。
横画面でも領域が不足する場合は縦積みなどへ退避する。数値や操作を縮小して収めない。
Foldカードは幅約52%を初期案とし、文字サイズや必要な最小幅を優先する。固定の半幅に無理に収めない。
横・Foldでは速度ラベルと値を1行にし、距離・時間を横並びにしてカードの高さを抑える。タッチ領域は縮小せず、開始／停止は48dp以上を実装時の基準とする。画面案ではカード高約234pxだが、文字拡大時に固定高で切り捨てない。
カードは大きめの角丸、テーマのサーフェス色と控えめな影で地図から区別し、透明なガラス表現にはしない。
全サイズでカードの四辺に地図が見える余白を設ける。縦・Foldでは地図操作を右上、横では左側に置く案とし、カード・下端の帰属表示・ナビゲーションと重ならないようにする。
スナックバーの表示領域もカード下にあらかじめ確保し、出現・消失時に配置を変えない。追従カメラもカードなどの占有領域を考慮し、現在地を隠さない。
初版のカード位置はアプリ側で決め、ドラッグによる自由配置機能は追加しない。

### 状態別の内容

| 状態 | 数値・地図 | 操作 |
|---|---|---|
| 待機 | 数値は「—」。現在地を表示可能なら表示 | 開始 |
| 測位待ち | 速度「—」、距離0、経過時間は進む | 停止 |
| 記録中 | 速度・距離・経過時間と軌跡 | 停止 |
| 取得不能 | 速度「—」、距離は取得できた分を保持、時間は進む。最後の位置を残す | 停止 |
| 停止後 | 数値は待機表示に戻す案。終了した軌跡を保持し、保存完了と履歴詳細への導線を表示 | 開始、履歴を見る |

地図の手動移動で追従を解除し、現在地ボタンで復帰。向きは北固定／進行方向を切り替える。
取得不能時は最後の位置を現在の測位と誤認しないよう、位置マーカーの状態表現を変える案とする。

## 3. ダイアログと案内

- 保存完了: MaterialのSnackbarを使い、下部バーの場合はその上、左側レールの場合は地図領域の下部に重ねて表示。「見る」で保存したセッションの履歴詳細へ移動する。時間経過で消え、常設ボタンは追加しない。
- Android実装ではSnackbarHostで管理し、表示時間はアクションとアクセシビリティ設定を考慮する。画面案の6秒は動作確認用の仮値で、製品仕様として固定しない。
- 参照: [Android公式Snackbar](https://developer.android.com/develop/ui/compose/components/snackbar)、[Navigation bar](https://developer.android.com/develop/ui/compose/components/navigation-bar)。

- 停止: 「記録を停止しますか？」、ボタンは「記録を続ける」「停止して保存」。確定まで記録は続く。
- 削除: 「この記録を削除しますか？」と日時を表示し、「キャンセル」「削除」。記録中のセッションには削除を用意しない。
- 端末の位置情報OFF: 「位置情報をONにしてください」。OKの後、ユーザーが設定を変更し、メインで再度開始する。自動開始しない。
- 権限不足: 必要性を説明してOSの権限要求へ進む。許可されなければ待機に戻る。
- 保存などの失敗: 成功表示を出さず、失敗した操作と次に取れる操作を提示する。回復動作の詳細は技術設計で決める。

## 4. 設定

縦方向のフォームを基本とする。広い画面でもフォームの行を過度に引き伸ばさない。

1. 取得間隔: 数値入力と「秒」。1〜60の整数のみ受け付け、「適用」で確定する案。編集中の空欄や範囲外値で現在の設定を変更しない。
2. 表示項目: 速度・距離・経過時間の表示スイッチと順序変更。ドラッグだけに依存せず上へ／下へ操作も用意する案。
3. 地図スタイル: ライト・ダーク・システムの選択。
4. 画面消灯防止: ON／OFFと「記録中にアプリを表示している間」の説明。

確定した設定は記録中も反映する。取得間隔の入力確定UI以外は個別操作で保存する案とする。
全項目を非表示にしても状態と開始／停止は残す案。自由配置・サイズ変更の編集UIは含めない。

## 5. 履歴一覧

- 行の主見出しは開始日時。補足に距離と経過時間を表示。
- 中断した記録は「中断」と明示する。
- 行のタップで詳細へ移動する。
- 初稿では新しい順に並べ、検索・フィルタ・一括削除は追加しない。
- 空の場合は「記録はまだありません」とメインへ戻る導線を表示する。
- 名前変更UIは置かず、将来日時見出しをユーザー指定名に置き換えられる構造にする。

## 6. 履歴詳細

- 軌跡全体が収まる地図と、開始日時・終了日時・距離・経過時間・平均速度・最高速度を表示する。
- 縦では地図の下、横では地図の右に集計を配置する案。
- 中断の状態を明示する。終了日時欄は中断時には「最終稼働確認」として時刻の意味を区別する案。
- 位置0点でも詳細を開けるようにし、「位置情報は記録されていません」と表示する。地図の代わりに空状態を出す案。
- 削除は詳細画面のメニューから実行する案。確認後、一覧へ戻る。
- 記録中でも過去の履歴は閲覧できる。上部の記録中表示からメインへ戻れる。

## 7. レビュー事項

- メインの縦画面で速度を大きくする案と、3項目を同じ大きさにする案のどちらが見やすいか。
- 縦の下部、横の右側、Foldの左下に浮かせたカードが用途に合うか。
- 左側レールと低めのカードを配置した横画面の地図領域が十分か。
- 停止後の数値を「—」に戻す案でよいか。
- 取得間隔の「適用」操作、全項目非表示、履歴の並び順など、初稿で追加した操作案。

## 8. 検証状況

合意済みの基本設計と配置・状態一覧を照合して作成した。画面案の数値はサンプル。
会話内のメイン画面案では配置、記録状態、開始・停止確認、地図操作の表示を比較できる。
第3案では全サイズのフローティングカード、下部ナビゲーション、時間経過で消える保存完了スナックバーを追加した。履歴・設定の画面案は遷移確認用の概要で、入力・削除などの操作は未実装。M3Eの厳密な仕様適合はAndroid実装時に確認する。
第4案では横・Foldを左側レールに変更し、カードを約234pxへ圧縮した。736px幅でレール配置とカード高、320px幅で下部バーへの退避、両方で停止前後の位置固定・スナックバーとの非重複・遷移をブラウザで確認した。
ブラウザで736px・320pxの各幅について縦・横・Foldを切り替え、停止前後のカード位置・寸法が同一であること、スナックバーがカード・ナビゲーションに重ならないこと、横方向にはみ出さないことを確認した。履歴詳細へのアクション、ナビゲーションの選択、スナックバーの自動消去も確認した。ホストが供給するアイコンの描画はこの単独ブラウザ検証には含まない。
実地図、Android実装、OS権限、実機でのタッチ領域・文字拡大・回転・Foldへの適合は未検証。
