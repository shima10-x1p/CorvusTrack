# CorvusTrack 基本設計・合意事項

更新日: 2026-09-13

参照資料: 「Android追跡アプリ構想」の会話、`android_tracking_app_requirements_mvp.md`、本プロジェクトでの追加検討。
本書は初期要件書に、その後の合意を反映したもの。未決事項は末尾に分けて記載する。

## 1. 目的と対象

ドライブや散歩などの移動を記録し、移動中の情報を見やすく表示するとともに、終了後に軌跡と移動情報を振り返れるAndroidアプリを作る。

- 個人利用を前提とする。
- 表示名は`CorvusTrack`、アプリIDは`net.shima10x1p.corvustrack`。
- 対応OSはAndroid 17以上。
- 地図にはMapbox Maps SDK for Androidを採用する。
- Mapboxの料金・利用条件は導入時に公式情報で確認する。本書で無料利用を保証するものではない。
- ドライブと散歩を別モードにせず、共通の移動記録として扱う。
- 地図は記録していないときも利用できる。
- ナビゲーション、経路検索、施設検索、渋滞案内はMVP対象外。
- 地図の事前ダウンロード機能は、初版だけでなく将来も対象外。

## 2. 画面構成と表示設計

基本画面は、メイン・設定・履歴一覧・履歴詳細の4画面とする。
デザインシステムはMaterial 3 Expressive（M3E）に従う。
画面遷移は「地図・履歴・設定」のナビゲーションを基本とし、メインのタイトルバーは置かない。履歴詳細は履歴配下として扱う。
縦・狭幅では下部ナビゲーションバー、横・Foldなど十分な幅がある場合は左側ナビゲーションレールに切り替える。具体的な切り替え条件は画面領域に基づいて決める。

### メイン画面

- 地図を主役とし、現在地と記録中の軌跡を表示する。
- 移動情報は現在速度・移動距離・経過時間を基本とする。
- 待機中と記録中で画面構成を大きく変えず、開始／停止ボタンと数値の状態を切り替える。
- 待機中の移動情報は「—」などの未計測表示とする。
- 記録中は原則として閲覧中心とし、余計な操作を要求しない。
- 記録停止後はメインに残り、今回の軌跡と保存完了の案内を表示する。案内から履歴詳細を開ける。
- 停止後の案内や導線でボタンの行を増やさず、メインの地図・情報・操作の配置を維持する。
- 保存完了の案内と履歴へのアクションにはスナックバーを使用する。
- 次の記録開始時に、メインの軌跡を新しいセッションへ切り替える。過去の軌跡は履歴で確認する。

### 画面領域への対応

- Pixel 8 Pro、Pixel 10 Pro Foldの内外画面、縦・横向きを想定する。
- 端末名による専用UIではなく、利用可能な幅・高さに応じて部品を再配置する。
- 縦画面は地図と下部の情報、横画面は地図とサイドパネルを基本案とする。
- Foldなど広い画面では、地図と情報の両方に領域を配分する。
- 縦・横・Foldとも、情報と記録操作は地図上のフローティングカードを基本とする。画面領域に応じてカードの幅と位置を変える。
- 具体的な配置や切り替え条件は画面設計で決める。

### 表示部品とカスタマイズ

- 初版から速度・距離・経過時間の表示／非表示と並び順を変更できる。
- 表示部品、配置設定、画面領域に応じたレイアウト処理を分離する。
- サイズ変更・自由配置の操作UIは初版に含めないが、後から追加できる構造とする。
- 平均速度、最高速度、高度、方角、現在時刻、GPS精度などの部品追加にも備える。
- 距離はkm、速度はkm/h、経過時間は「時:分:秒」で表示する。

## 3. 記録開始と終了

### 開始

- 必要な権限と端末設定が整っていれば、開始ボタン1回で記録を開始する。
- 位置情報権限がなくても、地図と履歴は閲覧できる。
- 記録開始時に必要な位置情報権限を求め、許可されなければ開始しない。
- 初回の権限取得が必要な場合は、許可後にセッションと時間計測を開始する。
- 端末の位置情報設定がOFFなら、「位置情報をONにしてください」とダイアログで案内する。
- OFFの場合の操作は「開始 → 案内 → OK → ユーザーが設定をON → 再度開始 → 記録開始」とする。
- 設定から戻っただけでは自動開始しない。再度開始を押した時点で設定を確認する。
- 開始条件を満たしていれば、測位完了を待たずセッションと時間計測を開始する。
- 測位前は「測位待ち」と表示し、取得後に軌跡と距離の記録を始める。
- 測位待ちは経過時間と平均速度の計算に含める。

### 停止

- 停止ボタンで確認ダイアログを表示する。
- 停止を確定するまでは記録を継続し、キャンセルした場合もそのまま継続する。
- 確定時にセッションを終了し、保存する。
- 位置情報0点、移動なし、短時間の記録も保存し、自動破棄しない。
- 削除はユーザーが履歴から明示的に行う。

## 4. 記録中の継続と中断

- 画面消灯中、別アプリ使用中も記録を継続する。
- 設定画面や履歴を開いても記録を継続し、閲覧・設定変更を可能とする。
- 記録中のセッション自体は削除できない。
- 通信圏外で地図を読み込めなくても、位置情報の記録は継続する。

### 位置情報の取得不能

- セッションと時間計測は継続する。
- 速度は「—」、状態は「位置情報を取得できません」と表示する。
- 現在地は最後に取得した位置に残す。
- 記録中に端末の位置情報設定がOFFになった場合も同じ扱いとする。
- ONに戻り測位できたら、同じセッションで位置の記録を再開する。
- 中断の短時間・長時間を区別せず、取得不能区間の前後は軌跡で結ばず、その区間の距離も加算しない。
- 取得不能区間も経過時間と平均速度の計算には含める。
- 設定した取得間隔による通常の点間は結び、距離を計算する。通常の取得間隔と取得不能の判別方法は未決。

### 記録処理の予期しない終了

- 保存済みデータを中断した記録として残し、自動再開しない。
- 位置情報とは別に、記録処理の稼働時刻を定期保存する。
- 最後に稼働を確認できた時刻までを記録時間とする。
- 次回起動時に中断した記録として扱い、履歴に「中断」と表示する。
- 稼働時刻の保存間隔は未決。実際の終了時刻と保存済み時刻には差が生じうる。

## 5. 地図操作・設定・通知

### 地図操作

- 手動で地図を動かすと現在地追従を解除する。
- 現在地ボタンで追従に戻る。
- 初期の向きは北固定とし、進行方向を上にする表示へ切り替えられる。

### 設定

| 設定 | 内容・初期値 | 記録中の反映 |
|---|---|---|
| 位置情報の取得間隔 | 1〜60秒を1秒単位の数値で指定。初期値1秒 | 同じセッションのまま変更後の位置取得に適用。既存の記録は保持 |
| 表示項目 | 速度・距離・経過時間の表示／非表示と並び順 | 即時 |
| 地図スタイル | ライト・ダーク・システム。初期値システム | 即時 |
| 画面消灯防止 | 初期値ON、変更可能。記録中かつアプリ表示中に適用 | 即時 |

取得間隔は位置取得への指定値として扱い、OSからの実際の配信タイミングや変更反映の詳細は実装時に確認する。

### 通知

- 記録中であることと経過時間を表示する。
- 通知のタップでアプリに戻る。
- location型Foreground Serviceを採用する。通知権限が拒否された場合の案内は実装前に詰める。詳細は[技術選定](technology-selection.md)を参照。

## 6. 記録データと保存

基本モデルは、1回の移動を表すTrackingSessionと、時系列のTrackingPointの2階層とする。

### セッションに必要な情報

- 開始日時、終了日時
- 総移動距離、経過時間、平均速度、最高速度
- 記録中・終了・中断を識別できる状態
- 最後に稼働を確認できた時刻

### 位置点に必要な情報

- 緯度・経度、取得日時
- 位置精度、速度、高度、方角
- 品質判定結果
- 軌跡の不連続区間を識別するための情報（具体的な保持方法は未決）

### 処理方針

1. 位置情報を取得する。
2. 取得した生データをその都度保存する。
3. 品質を判定する。
4. 有効な点を軌跡や距離などの集計に利用する。

- 終了時の一括保存にせず、予期しない停止でも取得済みデータを残せるようにする。
- 異常な点も削除せず、判定方法を変更した際に再計算できるようにする。
- 平均速度は総移動距離をセッション全体の経過時間で割る。停止・測位待ち・取得不能の時間を除外しない。
- 距離・最高速度の具体的な算出方法と品質判定の閾値は未決。
- 地図表示と位置記録処理を分離する。位置取得はFused Location Provider、記録保存はRoom、設定保存はDataStoreを採用する。選定理由と未検証事項は[技術選定](technology-selection.md)に記載する。

## 7. 履歴とデータ管理

- 一覧から記録日時や距離などが判別できるようにする。
- 詳細では軌跡の地図、開始・終了日時、距離、経過時間、平均速度、最高速度を表示する。
- 削除時は確認ダイアログを表示する。
- 名前変更は初版には含めないが、将来追加できる構造にする。
- 基本は端末内保存とする。
- 移行機能は現時点で設計を詰めない。将来はテキスト系の形式による書き出し・読み込みを想定し、形式は未定とする。
- 区間別の速度分析、速度グラフ、停止時間を除外した平均速度はMVP対象外。

## 8. 残っている設計・検証事項

| 項目 | 残っていること |
|---|---|
| Android実装基盤 | 技術は選定済み。SDK・ビルド・ライブラリの依存解決と最小ビルドによる検証が残る |
| 継続記録 | Foreground Service、権限、通知、OSによる終了・権限取り消しへの対処 |
| Mapbox導入 | SDK系列・トークン管理方式・公開料金を調査済み。アカウント接続と実表示は未確認 |
| 取得不能の検出 | 1〜60秒の通常の取得間隔と、取得不能による途切れの区別 |
| GPS品質判定 | 異常点の採否、前後の点を使う判定、軌跡の分割との関係 |
| 集計 | 距離・最高速度の算出方法、0点・経過時間0などの境界条件 |
| 稼働時刻 | 保存間隔と中断検出・確定処理 |
| 画面設計 | 各画面の配置、履歴一覧、レスポンシブ切り替え条件、各種状態の表現 |
| 表示詳細 | 数値の桁数、取得不能時の地図上の表現、進行方向が得られない場合の挙動 |
| 停止後の状態 | アプリ再起動後にも前回の軌跡をメインへ復元するか |
| 実機検証 | 消灯・別アプリ・測位不能・復帰・中断時の保存、電池消費、長時間記録、Foldと回転 |

画面案を初版のベースとし、技術選定まで実施済み。次の工程は依存関係の固定とAndroidプロジェクトの最小構築・検証とする。
